Compile, test and deploy Solidity in seconds, not minutes

plain is one small binary that compiles, tests, deploys, verifies and upgrades your contracts. It runs your Foundry project as it is, needs nothing else installed, and turns the minute-long edit-and-test loop into about a second.

curl -fsSL https://getplain.org/install | sh

The installer works on macOS and Linux. plain is also on Homebrew, apt, dnf, Nix, mise and crates.io, as the install guide shows.

# a Counter contract and its test, in an empty folder
plain init
# run every test, then again whenever you save
plain test --watch
# or pick every step from a menu
plain

From an empty folder to an upgraded contract in six steps

Each step is one command, the same in a new project or in the Foundry project you already have. If you'd rather not remember them, run plain on its own: a menu walks you through every step, shows the command it runs, and asks for keys without echoing them.

$ plain ? What next? ❯ Build compile the contracts Test run the tests, once or on every save Deploy put a contract on a chain, local or live Verify publish the source code on block explorers Upgrade point a proxy at a new implementation Settings deployer accounts, Etherscan key, RPCs
  1. 1

    Write

    Start from a contract and its test, or open the project you already have. forge-std is built in, and OpenZeppelin works straight from npm.

    plain init
  2. 2

    Compile

    The right solc comes from your pragmas and downloads once, and files you haven't changed come from the cache.

    plain build
  3. 3

    Test

    Every test runs, then runs again each time you save, and a compile error just waits for your fix.

    plain test --watch
  4. 4

    Deploy

    A key made by plain account new stays encrypted with your password. Every chain on chainlist.org works by name, and a simulation shows the gas and the cost before anything is sent.

    plain deploy Counter --network base-sepolia --account deployer --broadcast
  5. 5

    Verify

    Deploys verify on Sourcify, Blockscout and Etherscan by themselves. When you'd rather verify by hand, plain writes the JSON to upload and every value the explorer's form asks for.

    plain verify --network base-sepolia --export
  6. 6

    Upgrade

    --proxy deploys behind an OpenZeppelin proxy, and an upgrade goes out only after plain has checked that the new code keeps the proxy's storage.

    plain upgrade Box --network base-sepolia --account deployer --broadcast

The docs cover each step in detail, from getting testnet funds to verifying a contract by hand.

Nothing to set up before your first test

plain replaces a toolchain with a single command, so a new project or a fresh clone is ready as soon as the binary is on your PATH.

One binary and nothing around it

plain is a single 7 MB executable. You don't need Node, npm or git submodules, and forge-std is built in, so import {Test} from "forge-std/Test.sol" works in an empty folder.

Your Foundry project already works

plain reads foundry.toml, remappings and lib/ the way they are, picks the solc version your pragmas ask for, and downloads it the first time you build.

A menu when you want one

Run plain on its own to build, test, deploy, verify and upgrade from a menu. It asks only what each step needs and prints the command it runs, so the next time you can type it yourself.

Keys that stay encrypted

plain account new makes a deployer key encrypted with your password, in the keystore format Foundry's cast uses, so no private key has to sit in a .env file.

Deploys that verify themselves

plain deploy runs your script against a fork first, sends the transactions only when every one of them would succeed, and then verifies each new contract on Sourcify, Blockscout and, with your API key, Etherscan.

Every chain by its name

Pass --network base, linea or a chain id, and plain finds a working public RPC on chainlist.org, while your own RPC URLs still take priority.

Why it's fast

  • Test files no longer recompile the contracts they deploy, so editing a contract recompiles that contract and leaves the tests alone.
  • Editing one test recompiles just that test, and suites whose code and inputs haven't changed reuse their last results instead of running again.
  • Big test files compile in parallel, and solc jobs are scheduled from the timings of your previous build, with a cache that every clone and worktree shares.
  • Deploys batch their network round trips, so a 40-transaction deploy makes 13 requests to the RPC where sending and checking one at a time would take 77.
